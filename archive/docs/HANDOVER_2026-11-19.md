## 3. vc83 — what is on the phone right now

`170328b` ("DECLINE disjoint revert, arming readiness gate, planner/FX/native fixes"). Four substantive moves:

1. **DECLINE reverted** to vc81 disjoint exponents (`p^0.5` out, `p^1.9` in). vc82's equal-power pair measured +3.13 dB central RMS in synthetic renders, but was never heard as better, and the council could not tie it to any executed complaint. Reverted rather than shipped on a theory.
2. **`driveArming()` readiness gate** — a *measured* defect, not a hypothesis. On unchanged vc82 source, a fake-clock controller rig showed: while incoming deck `B` stays `STATE_BUFFERING` (`playWhenReady=false`, volume 0), `driveArming()` already commands outgoing `A`'s low-pass to ~800 Hz with `A` at gain 1.0. When `B` turns `READY` halfway through a `192–196 s` plan, `startFade()` anchors `fadeOutOriginMs` at `194000` and the first `FADING` tick reopens `A` to 7 kHz. Audible result would be *muffle → un-muffle* on a solo deck. vc83 pre-filters `A` only when `B` is `READY` and before the fade point, and adds `cancelArming()` for disable/pause/seek/timeout plus injected `nowMs`.
3. **Planner/FX**: loop-length bars fix, dual-confidence `sameBeatBlend`, peak-aware veto floor, measured FX eligibility gate, `LOOP_ROLL` restricted to `DJ_BLEND` + measured only, 4-beat roll capped at `ring/2` with 0.7 wet.
4. **Native**: `TptHighpass` v0–v2, chunked render, `echoWetRetireStart` gain fallback clamped to `max(gainZero, stopAt - 1s)`.

**Proven:** cue phase3 full suite `1934 tests, 0 failures, 0 errors, 1 skip`; native selftest, `--reverb-stop-probe`, `--loop-domain-probe` (63 pairs) all exit 0; signed v2+v3, audit PASSED, 16 KiB aligned.

**Not proven:** whether the arming gate removes anything the user actually hears. No listening verdict for vc83 exists in this repo.

## 7. Build and release contract

### 7.1 Hard rules

- **No Android or Gradle builds on this workstation.** Simulation-tier box only. `cue` is the build host; GitHub Actions is CI/fallback.
- Gradle: `--max-workers=4`, `-Dorg.gradle.jvmargs=-Xmx5g`. No swap, earlyoom is live, 8 vCPU / 23 GiB.
- Release: **unsigned build → `apksigner` CLI v2+v3**. Gradle signing on AGP 8.13.1 emits v2 only; do not "simplify" back to it.
- Signing material: `/root/.bitchord-secrets/bitchord-loopfix.jks` (0600) + `keystore.properties`. **Never** cat, copy, export, or commit. Certificate SHA-256 `20c66ad6ab1a1d1f14f4b31966e8cb0cc591e39356687006989a6f2172e3fe4c`.

### 7.3 Known wrapper defects (unfixed, record them)

The wrapper is `/usr/local/bin/cue-android` on cue (2,824 B, last touched 2026-11-17 12:58). I read it end to end this session. Three real hazards:

- **`REPO` is hardcoded to `/workspace/src/bitchord-mix`** — the preserved vc82 checkout (`60b9734`, versionCode **82**), *not* whatever tree you are in. Running `cue-android apk` from the vc84 worktree still builds vc82, signs it, and installs it over a newer build. Always pass an explicit tree, or edit `REPO`, or invoke Gradle directly in the target worktree.
- **`native` omits the real gate.** It builds `--selftest`, `--reverb-stop-probe`, `--loop-domain-probe` and a vocal-spectrogram test, but not window calibration or sanitizers, and not `native/loopmix/loop_mix_sound_polish_test.cpp`. Run `tools/vc75-gate.sh` explicitly for a real gate.
- **The keystore move is not crash-safe.** `apk` does `mv keystore.properties /tmp/kp.hold` with an EXIT trap. A SIGKILL, OOM, or VM freeze mid-build leaves the file displaced — check for `/tmp/kp.hold` before any build that expects signing material. Never run two builds at once.

The signed output path *is* present and correct: `app/build/outputs/apk/prod/release/app-prod-arm64-v8a-release.apk`, signed by `apksigner` CLI with v2+v3, verified with `--print-certs`. (An earlier note in this repo claimed the path was missing; that was wrong.) A stale vc82 signed APK currently sits there — 67,552,565 B, built 2026-11-17 20:43.

### 8.1 The state machine

`Phase { IDLE, ARMING, FADING, TAIL, LOOP, LOOP_ARMING, LOOP_RUNNING, BAILING, SLEEP }`

- `ARMING` — plan accepted, outgoing deck may be pre-filtered, incoming buffering. **This is where vc83 added its readiness gate.**
- `FADING` — classic gain/filter cross in progress.
- `TAIL` — the dissolve after handoff; 350 ms when the guard fires.
- `LOOP_*` — native renderer owns both decks; `LOOP_RUNNING` until `finishLoop()`.
- `BAILING` — abort path back to the classic engine.

## 14. Glossary

- **DECLINE** — the 4 s filtered handoff used for pairs the policy declines to beatmatch, rendered as a separation ride rather than a sweep.
- **LOOP_RUNNING** — native renderer owns both decks; handover is judged on presentation clocks, not media positions.
- **`RetireGuard`** — the rule that an audible spare deck must be dissolved rather than cut. `audible(volume)` decides; when it is true at `finish()`, the completion reason becomes `emergency-retire-guard`.
- **Exit gate** — a hard assertion set on the native renderer's tail: no step above threshold, wet output reaches silence by `stopAt`. Violations > 0 is a real defect.
- **`build-missed-splice`** — the loop build did not finish inside its budget before the splice point; the engine falls back to a soft classic mix.
- **`crng reseeded due to virtual machine fork`** — the cue freeze marker. Not a crash.
- **A/B selftest** — `loopmix --selftest`, 6 renders, checks first-frame geometry and the reverb tail. Cheap, always worth running.
- **63-pair loop-domain probe** — the finite/infinite loop source coverage test (54 ramp + 9 unity). If it changes, playback coverage changed.
