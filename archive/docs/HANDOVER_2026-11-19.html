00

The rule that cost the most

Every rejected build in this repository's history broke the same rule. Read it once and keep it.

Nothing is “fixed” by tests, commits, or a green CI run. The binding acceptance signal is the user's ears on the target phone, corroborated by telemetry from that same session.

Synthetic renders prove a command trajectory. A test count proves the code compiles and a contract holds. Neither says a human heard anything better — and this project has produced “this is the worst version ever” from a fully green tree.

When documents disagree, this order decides: live device state, then cue's retained evidence directories with their XML and exit codes, then this page, then anything dated before today — which is history, often describing a design that was later reverted.

What “accepted” is allowed to mean

vc80 covers exactly one thing: the finite-loop dropout on Touch the Sky → Higher Love. It is not a general stutter fix — the 64–85 ms gaps in the USB capture remain unexplained.

vc81 covers planning continuity. Force-closing and reopening no longer kills Automix after one song, because the ticker now survives a recoverable exception and SongSections no longer throws on a lyric cue inside 300 ms of the content end.

The feedback that doesn't count

vc82's “even better” arrived before the APK was confirmed installed — the device snapshot still showed versionCode 81 with no running session. It cannot be attributed to vc82 audio, and it is not acceptance of the overlap change.

Recording that honestly is cheaper than shipping on it.

02

What is playing right now

vc83 · 170328b · DECLINE disjoint revert, arming readiness gate, planner/FX/native fixes.

Four moves, one of them measured

DECLINE reverted to vc81's disjoint exponents. vc82's complementary faders measured +3.13 dB central summed RMS in production-filter renders, but were never heard as better and could not be tied to any executed complaint. Reverted rather than shipped on a theory.

Arming readiness gate — and this one came from a real rig, not a hunch. On unchanged vc82 source, while the incoming deck sat in STATE_BUFFERING at volume 0, the controller had already pulled the outgoing deck's low-pass to ~800 Hz with its gain still at 1.0. When the incoming deck turned ready halfway through the plan, the fade re-anchored and reopened the filter to 7 kHz. A solo deck, muffled and then un-muffled. vc83 pre-filters only when the incoming deck is actually ready, and cancels the arming on disable, pause, seek and timeout.

Planner & FX — loop-length bars, dual-confidence blending, peak-aware veto floor, measured-only effect eligibility, and a 4-beat roll capped at half the ring.

Native — high-pass revisions, chunked rendering, bounded echo retirement.

Two facts worth acting on

A quarter of all mixes take the emergency branch. Nine of 36 completions ended emergency-retire-guard — every one in TAIL, every one at tailMs=350, every one with no expected handover. The guard fires when finish() finds a spare deck still audible, and dissolves it instead of cutting it. That it exists is reassuring. That it fires this often is not “normal fades”.

Two pauses with no author. Both report playWhenReady=false at volume 1.0 with changeReason=1; the second lands 253 ms after handoff. Media3 calls that value a user request — but no command was sent, and this is how a spurious internal pause has looked in earlier captures. Neither proven, neither dismissed.

The noisy channel

53 rejections per 74 plans sounds catastrophic and isn't. It is replanning churn: scrubs, decline handoffs, fallback windows. Which means “count of fires” is a bad proxy for “count of good mixes.”

Style choice is worth a look. Since vc83 the engine picked DJ_FILTER 43 times, EQUAL_POWER 12, phrase template M1 12, DJ_BLEND 4. The filtered classic path dominates. Before tuning phrase templates, find out whether they are being vetoed by policy or simply losing on score.

Release builds strip Log.*. This JSONL file is the only transition evidence that exists on a shipped build.

Why it still waits

Three P1 reviews are open in the tree — phrase takeover double-counting, M7 stop-gain, straight-roll resume. Shipping past an open P1, on a build whose sibling was rejected, is how this project loses a week.

Nothing has been heard. A merge of three feature blocks is precisely the change that passes every test and sounds wrong.

Six rules for stating evidence. Never turn a test count into a quality claim. Never call a stage passed from an invocation that exited non-zero. Never identify a song pair from duration or BPM coincidence — mix.dump carries the ids, and without them the pair is unknown. Never report a cumulative counter as a per-version rate. A synthetic render establishes a command trajectory, not audibility. And a mix.verify ok is scoped to phase and exit gate only — it is not a verdict.

07

Hard limits

Not preferences. Each of these has already cost a day, a build, or a user's trust.

Never build or promote the rejected integration branch. It starved effects and dropped non-4/4 handling. It is preserved, not pending.

Never reset a cue checkout. One preserved test diff there is the only characterisation evidence for the arming defect. git clean deletes it.

Never touch signing material. No read, no copy, no print, no commit. The certificate is the sole reason in-place updates work.

Never run Android or Gradle builds on this workstation. It cannot, and trying wastes the session.

Never install without a version bump. adb install -r cannot downgrade; a failed attempt leaves the device in an unknown state.

Never uninstall, clear data, or replace the queue. The queue and session on the device are user state and evidence at once.

Never enable the NPU path while agreement fails and no HTP trace exists. Matching input shapes do not mean matching weights.

Never run cue-android from a newer worktree. Its REPO is hardcoded to the preserved vc82 checkout (versionCode 82), so it would build, sign and install vc82 over a newer build. Invoke Gradle in the target tree instead.

Never ship past an open P1, and never ship without a listening verdict.

Never reintroduce the delayed limiter (linear interpolation cannot detect intersample overshoot), the keep-warm daemon (it never prevented a freeze), or Gradle signing (v2 only).
