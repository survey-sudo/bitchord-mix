# Bundled NPU stack (vc70)

Mirrors Orchard mobile/android/npu-addon: the Maven onnxruntime-android AAR
carries no QNN execution provider, so BitChord builds ONNX Runtime 1.31.0
from source with the QNN EP linked in, and bundles the QAIRT 2.51.0.260929
HTP libraries in the app APK (app/build.gradle.kts adds
npu-addon/prebuilt/jniLibs as a jniLibs source set and prefers the local
libonnxruntime.so through packaging pickFirsts, Orchard style).

Unlike Orchard there is no separate download: the stack ships in the main
APK (BitChord has no add-on host), compressed with legacy jniLibs
packaging. Two QAIRT HTP generations are bundled, V73 and V75: the sole
target (Poco F6, SM8635) cannot be pinned to one of them from the QAIRT
2.51 sources on hand (the SDK's socModel enum carries no arch column, and
the driver's SoC-to-arch table is built at runtime), so both ride along
and the driver resolves the arch from the SoC at backend open (no htp_arch
provider option is set). The DSP picks its own Skel through
ADSP_LIBRARY_PATH, which the app sets at startup (NpuNative /
npu_jni.cpp, the same value Orchard qnn_runner uses).

## Layout

- build-ort.sh: the recipe (needs ORT_SRC, QNN_SDK, ANDROID_HOME).
- ops.config: ops allowed in the reduced ORT build, generated by the
  ORT create_reduced_build_config.py from the two models BitChord ships.
- prebuilt/jniLibs/arm64-v8a: stripped libonnxruntime.so + QAIRT libs.

## QAIRT SDK subset

The Qualcomm zip is 2.8 GB; only these files are needed:

- lib/aarch64-android/libQnnHtp.so, libQnnSystem.so,
  libQnnHtpPrepare.so, libQnnHtpV{73,75}Stub.so
- lib/hexagon-v{73,75}/unsigned/libQnnHtpV*Skel.so
- include/QNN/ for the ORT build

Download: https://softwarecenter.qualcomm.com/api/download/software/sdks/Qualcomm_AI_Runtime_Community/All/2.51.0.260929/v2.51.0.260929.zip

## Runtime

Only Qualcomm devices attempt QNN (NpuSupport.detectVendor + bundled
backend path). Everything else, and any QNN open failure, runs on the
CPU execution provider: the NPU is an optimization, never a requirement.
Log tag BitChordNPU in logcat: init prints the SoC string, the bundled
backend path, and which Skel file(s) are present in nativeLibraryDir, so
the device proves the resolved arch; a QNN session failure prints a
warning through AnalysisLog.
